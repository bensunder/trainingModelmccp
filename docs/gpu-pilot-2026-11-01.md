# GPU pilot, 2026-11-01

First real run of the MCCP GPU path: QLoRA SFT on Qwen3-8B through the production
dataset pipeline, trainer contract, vLLM serving, L0 publish guard and L1 evaluation.
Driver: `deploy/gpu/pilot.py` + `deploy/gpu/run_pilot.sh` (no Docker, no control-plane DB).

| | |
|---|---|
| GPU | 1x NVIDIA RTX 4000 Ada, 20 GB, driver 615.71 (GridShare community host, Ubuntu 22.04) |

## Bugs found by the pilot (fixed, with regression tests)

1. **Eval requests rejected by vLLM** (`mccp.evals.layers`). Golden conversations replayed
   tool calls without `id`, with object `arguments`, and tool results without
   `tool_call_id`; vLLM returns 400. The in-process fake accepted them. `golden_items` now
   emits the OpenAI wire format with deterministic call ids.
2. **Train/serve skew in tool arguments** (`mccp.datasets`). Arrow-backed loading
   (`Dataset.from_list`, as Soup uses) unified object arguments into one struct, so
   `lookup_po` trained as `{"po_number": ..., "vendor_id": null}` and the adapter emitted the
   nulls (run 1: 0% exact tool calls). Arguments are now exported as JSON strings, and the
   trainer pre-flight refuses object arguments and proves on the real tokenizer that string
   and object forms render token-identically (`tool_argument_render_checks: 20` in run 2).

## Host notes for single 20-24 GB cards

- Cap `--max-num-seqs` (vLLM's default 256 OOMs the warm-up next to a 16 GB bf16 model).
- vLLM JIT-builds kernels: needs `ninja` on PATH. FlashInfer's sampling kernel failed to
  build against the host CUDA 12 toolkit, so the pilot sets `VLLM_USE_FLASHINFER_SAMPLER=0`.
- Community hosts vary: the first host had no outbound HTTPS. Check GitHub, PyPI and
  Hugging Face reachability before installing anything.
